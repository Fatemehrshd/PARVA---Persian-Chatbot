# وضعیت و معماری داشبورد و ادمین در بک‌اند (Backend Admin Architecture & ApiFeatures)

این سند معماری کنترلرهای ادمین در لایه NestJS، کلاس جامع `ApiFeatures` و نحوه پردازش پارامترهای کوئری در سمت سرور را تشریح می‌کند.

---

## ۱. ماژول‌ها و کنترلرهای ادمین (Admin Controllers)

تمام قابلیت‌های مدیریتی تحت گارد احراز هویت `JwtAuthGuard` و گارد نقش `AdminGuard` ایمن‌سازی شده‌اند:

```
backend/src/modules/
├── admin/
│   ├── admin-dashboard.controller.ts     ← آمارهای تجمیعی داشبورد (KPI Metrics)
│   ├── admin-users.controller.ts         ← مدیریت، جستجو و فیلتر کاربران
│   ├── admin-conversations.controller.ts ← تاریخچه چت‌ها، پیام‌ها و جزئیات مکالمه
│   ├── admin-files.controller.ts         ← آمار، وضعیت و محتوای استخراج‌شده فایل‌ها
│   └── admin-settings.controller.ts      ← سقف توکن سراسری، پرامپت و تنظیمات آپلود
└── models-admin/
    ├── models-admin.controller.ts        ← افزودن، ویرایش، وضعیت و سورت مدل‌های هوش مصنوعی
    └── providers-admin.controller.ts     ← مدیریت ارائه‌دهندگان و پیکربندی Base URL
```

---

## ۲. کلاس جامع `ApiFeatures` (`backend/src/shared/api-features.ts`)

یک کلاس ماژولار و سراسری است که مسئولیت استانداردسازی و پردازش تمام عملیات زیر را در درخواست‌های `GET` بر عهده دارد:

### ساختار متدها و قابلیت‌ها:
1. **جستجوی متنی چندفیلدی (`search`)**:
   - جستجوی غیرحساس به حروف بزرگ و کوچک (`LOWER(CAST(field AS text)) LIKE :q`)
   - در صورت ارسال پارامتر `search` یا `q`، فیلدهای مشخص‌شده در مدل پایگاه‌داده مورد جستجو قرار می‌گیرند.
2. **فیلتر مقادیر ستونی (`filter`)**:
   - فیلتر کردن دقیق روی مقادیر بولی (`isActive: true/false`)، فیلتر نقش (`role: 'admin' | 'user'`)، وضعیت فایل (`status: 'processed' | 'failed'`) و ارائه‌دهنده (`provider`).
3. **مرتب‌سازی داینامیک (`sort`)**:
   - مرتب‌سازی بر اساس نام ستون دلخواه با پارامتر `sortBy` و جهت مرتب‌سازی با `sortOrder` (`ASC` یا `DESC`).
4. **صفحه‌بندی (`paginate`)**:
   - محاسبه خودکار آفست و لیمیت (`skip` و `take`).
   - خروجی استاندارد پیجینیشن شامل:
     - `items`: آرایه رکوردهای صفحه جاری
     - `total`: کل رکوردهای منطبق
     - `page`: شماره صفحه جاری
     - `limit`: اندازه صفحه
     - `totalPages`: تعداد کل صفحات

### استفاده دوگانه (Dual Engine):
- **موتور TypeORM SelectQueryBuilder (`apiFeatures.exec()`)**: برای کوئری‌های مستقیم و با بهره‌وری بالا روی دیتابیس PostgreSQL (نظیر جدول فایل‌ها و لاگ‌ها).
- **موتور حافظه‌ای آرایه‌ها (`ApiFeatures.applyToArray(items, query, options)`)**: برای موجودیت‌های کش‌شده یا پردازش‌شده (نظیر کاربران، مدل‌ها و ارائه‌دهنده‌ها).

## ۳. نگاشت پارامترهای ارسالی از کلاینت به متدهای کنترلر

| پارامتر کوئری | نوع داده | مثال | عملکرد در بک‌اند |
| :--- | :--- | :--- | :--- |
| `search` یا `q` | رشته | `?search=gpt-4` | جستجوی متنی روی فیلدهای هدف توسط `search()` |
| `page` | عدد | `?page=2` | تعیین شماره صفحه برای واکشی |
| `limit` | عدد | `?limit=25` | تعداد آیتم‌های بازگشتی در هر صفحه |
| `sortBy` | رشته | `?sortBy=usedTokens` | فیلد مبنای مرتب‌سازی |
| `sortOrder` | رشته | `?sortOrder=DESC` | جهت مرتب‌سازی (`ASC` صعودی یا `DESC` نزولی) |
| فیلترهای ستونی | مقداری | `?role=admin&isActive=true` | فیلتر دقیق مقادیر توسط `filter()` |

## ۴. ساختار خروجی استاندارد API

هنگامی که درخواست با پارامترهای صفحه‌بندی ارسال می‌شود:
```json
{
  "success": true,
  "message": "Operation successful",
  "data": {
    "items": [
      { "id": "...", "name": "...", "createdAt": "..." }
    ],
    "total": 42,
    "page": 1,
    "limit": 10,
    "totalPages": 5
  }
}
```
در صورتی که درخواستی بدون پارامتر صفحه‌بندی فراخوانی شود، جهت حفظ سازگاری کامل با تست‌های سیستم، آرایه تخت برگردانده می‌شود.
